# Codebase audit and repair pass — 2026-11-08

## Method

- Read `README.md` first and treated it as the product/source-of-truth baseline.
- Used Impeccable 4.8.1's native Android workflow: source audit → harden → animate/layout → polish.
  The web detector/browser overlay was intentionally not run: this is a Compose + canvas Android app,
  and Impeccable's native audit route explicitly excludes web markup scanning.
- Reviewed every Kotlin source file, the manifest/accessibility config, Gradle setup, and resources.
- Apple reference: compact Live Activities use leading/trailing content around the sensor region;
  expanded layouts should preserve that relationship, use standard margins (20 pt, tighter for
  graphics/buttons), and change height with the amount of content.
  [1](https://developers.apple.com/design/human-interface-guidelines/components/system-experiences/live-activities)
  [6](https://developer.apple.com/videos/play/wwdc2023/10194/)

## Baseline audit score

Source-level baseline before this pass; not a rendered/device score.

| Dimension | Score | Key finding |
| --- | ---: | --- |
| Accessibility | 1/4 | Canvas controls had no virtual nodes; chips/swatches were below 48 dp; no animator-scale path. |
| Performance | 2/4 | Per-glyph text animation allocated/shaped fragments every frame; Euler springs were refresh-rate dependent; artwork resampled on metadata callbacks. |
| Appearance/theming | 3/4 | Coherent Nothing palette, but overlay colors were scattered and expanded cards did not match the Apple reference. |
| Platform conformance | 2/4 | Touch shield consumed gestures during morphs; drag/secondary-pointer releases could activate controls; reply fallback sent a result-less RemoteInput intent. |
| Adaptivity | 2/4 | Expanded width/height could overflow narrow displays; expanded content stayed in narrow side columns instead of using the area below the lens. |
| **Total** | **10/20** | Acceptable baseline with release-blocking interaction/layout defects. |

## Fixed findings

| Priority | Finding | Repair |
| --- | --- | --- |
| P1 | Expanded media/timer/notification layouts split the whole card around the lens and wasted the lower region. | Added `IslandLayout`: compact leading/trailing regions; expanded sensor-safe top row plus full-width lower region; content-aware heights; Apple screen-class widths clamped to the display. |
| P1 | Touch handling fired after drags, secondary-pointer releases, or content changes mid-press. | Pointer-id tracking, touch-slop cancellation, cancel-on-content/presentation change, no targets while morphing, charging confirmation no longer consumes touches. |
| P1 | TalkBack could not reach canvas transport/timer/notification actions. | Rest-state virtual `AccessibilityNodeProvider` buttons on the input window, with labels, bounds, click and focus actions. Needs device verification. |
| P1 | Inline-reply fallback fired a RemoteInput action without results. | Reply actions require a PendingIntent; fallback opens the conversation content intent; failed sends no longer clear the alert; stale reply windows close when their notification disappears. |
| P1 | Private notification content could be mirrored on a locked keyguard. | Secret notifications skipped; private notifications redacted to app label/generic body/app icon with no actions or content intent while locked. |
| P2 | Spring trajectory depended on refresh rate; per-character reveal broke shaping and allocated per frame. | Closed-form underdamped spring in `IslandMotion`; whole-line fade/rise replacement; bounded save-layer; reusable frame/paint paths; system animator scale respected. |
| P2 | Media sessions with initially empty metadata were ignored; unsupported transport buttons were active; artwork was resampled repeatedly. | Attach before metadata arrives, advertise transport capabilities, cache downscaled art/accent by bitmap identity, use the playback state's position timestamp. |
| P2 | `FULL` charging state was stored but rendered as `100%`; first plug event could be debounced at boot. | Render `FULL`, green bolt, initialize debounce so the first real transition is not suppressed. |
| P2 | Settings chips/swatches were small, rows could overflow, disabled button labels stayed white, status claimed ACTIVE from grant alone. | 48 dp targets, wrapping chip/swatch rows, selected semantics, whole-row switches, content-color labels, separate enabled/running status. |
| P2 | README described obsolete geometry/behavior and unverified frame timing. | Updated layout, motion/API-level, privacy, calibration, test and roadmap documentation; removed the measured-frame-time claim. |
| P3 | Dead/inverted fullscreen hide path pretended to work while window-content retrieval was disabled. | Initially removed the dead path; the follow-up fix pass enforces it through own-probe status-bar insets while still keeping `canRetrieveWindowContent=false`. |

## Compatibility flags

- `TimerModule.start(durationMs)` now **rejects** durations outside `1..24h` instead of silently
  clamping them. The shipped UI only passes valid presets.
- Expanded island geometry is intentionally different: wider Apple-class cards, content-aware
  heights, 44 dp expanded corner, and full-width lower controls. Compact calibration remains valid.
- Unsupported media transport controls are disabled instead of silently sending unsupported commands.
- Notification mirroring is redacted on a locked keyguard unless the notification is public.
- Tap-to-expand and single-active-source priority are preserved from the README. Apple's tap-to-open /
  long-press-to-expand and detached minimal two-activity presentation are **not** claimed as implemented.

## Device QA required before release

1. `mise exec java@openjdk-21 -- ./gradlew testDebugUnitTest assembleDebug` on the README toolchain.
2. Install on a Nothing OS 120 Hz device; verify compact lens flanking and expanded lower-region layouts
   for media, timer, notification with/without actions, charging, long/RTL/emoji text, font scale 1.3.
3. Interrupt/reverse morphs; drag off controls; add a second finger; cancel gestures; verify no accidental
   activation and no status-bar gesture swallowing outside the shell.
4. TalkBack: focus and activate body/transport/timer/notification virtual buttons.
5. Animator duration scale 0: state changes snap without spatial motion; restore the user's setting after.
6. Lockscreen privacy: public vs private vs secret notifications; inline reply success/failure/fallback.
7. Media: session starts with empty metadata then updates; unsupported actions; artwork accent/cache.
8. Narrow/landscape/folded display and extreme lens calibration: no clipping or lens overlap.

## Follow-up hotfix: island disappeared after fullscreen suppression shipped

- Symptom: island could remain hidden everywhere after PR #2 because the accessibility-overlay inset
  probe reported `statusBars` invisible while the normal system UI was visible.
- Cause: the probe used fullscreen-friendly layout flags (`FLAG_LAYOUT_IN_SCREEN` / cutout-always)
  and any uncalibrated `false` reading was treated as authoritative fullscreen.
- Fix: probe now uses normal non-focusable overlay layout; a `StatusBarVisibilityGate` treats hidden
  readings as unknown until the probe has observed a visible status bar; service-context metrics are
  no longer used as a fallback truth source; suppression transitions and probe calibration are logged.
- Regression coverage: fail-open before calibration, suppression only after visible-then-hidden,
  reset returns to fail-open, unknown insets still do not suppress.
